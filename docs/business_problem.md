# Business Problem

## Scenario

A retail business wants to understand historical online transaction data so it can review sales performance, customer behaviour, product performance, country-level revenue contribution, and return or cancellation patterns.

The business needs a clean, repeatable analysis process before using the data for reporting or decision-making. Transaction datasets often include missing customer IDs, cancelled invoices, negative quantities, non-product stock codes, and incomplete periods. These issues can distort revenue and customer analysis if they are not handled clearly.

## Why This Analysis Matters

This analysis helps answer practical commercial questions:

- Which months generate the most revenue?
- Which products and customers contribute most to sales?
- Which countries contribute most revenue?
- Is revenue concentrated among a small number of customers or products?
- Which transactions should be treated as valid sales, cancellations, or returns?

## Intended Use

This repository is intended as a Python / pandas exploratory data analysis project. It is not presented as work experience or as a production reporting system.

The analysis demonstrates how Python can be used to inspect, clean, group, summarise, visualise, and communicate findings from retail transaction data.
